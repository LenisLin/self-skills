# Reviewer Response

Produce a direct answer to each reviewer request, followed by that comment's necessary manuscript modifications. Use the author's requested language and delivery format.

## Scope and Reading

Identify files by their roles, not by fixed names or project paths. Follow current author instructions and applicable project contracts. Discussion and drafting do not authorize editing publication files, running analyses, or publishing material.

- Before planning or drafting, read `references/01_response_planning_and_drafting.md` and `references/02_evidence_scope_and_claims.md`.
- For quotations, figures, tables, or manuscript changes, also read `references/03_manuscript_changes_and_matrices.md`.
- Before reading or editing Office files, read `references/04_document_editing_and_validation.md`.
- Consult `examples/response_schemes.md` for worked response shapes. Adapt examples to verified source material rather than copying their facts.

## Workflow

1. Establish the task. Identify the reviewer comments, review-round baseline, current working manuscript and supplement, prior responses, relevant outputs, and authorized deliverable. Confirm which files are current and whether editing is requested.
2. Extract operative keywords. Read the complete comment and identify each requested action, object, and qualifier. Separate mandatory requests from examples and background. Confirm that no request has disappeared through summarization.
3. Confirm intent. State what the reviewer needs and what the author wants delivered now. Ask a focused question only when ambiguity changes correctness, scope, completion status, or authority; otherwise state the interpretation and continue.
4. Inspect current support, then match history. Read relevant current passages before prior responses. Follow the historical-matching procedure in `references/02_evidence_scope_and_claims.md`. Confirm which requests are already covered, partly covered, or unresolved.
5. Present the response strategy before the complete draft. Briefly identify the point to answer, usable evidence, existing manuscript support, necessary local changes, and unresolved items. Confirm that each proposed action serves an operative request; no configuration form is required.
6. Draft the substantive response. Follow `references/01_response_planning_and_drafting.md`. Confirm that each request receives a direct answer and that unfinished work is not presented as completed.
7. Append this comment's modification material. Follow `references/03_manuscript_changes_and_matrices.md`. Confirm that completed revisions and proposed next-version changes remain distinct.
8. Check and deliver. Verify request coverage, evidence labels, quotations, action verbs, titles, formatting, and unresolved placeholders. If files were edited, perform the checks in `references/04_document_editing_and_validation.md`. Report only checks actually performed.

When the author updates the working manuscript, return to the affected source passages and refresh their historical matches, quotations, matrices, and locations before reusing the response.
